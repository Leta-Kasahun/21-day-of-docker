## Day 15 Docker Volumes

### What is a Docker Volume?

- A **volume** is a special storage location managed by Docker.  
- Unlike bind mounts, volumes are **independent of container directories**.  
- Data in volumes **survives container deletion**, making it ideal for production-grade apps.  
- Multiple containers can **share a single volume**, allowing data sharing and collaboration.

> Official Docker Docs reference: [https://docs.docker.com/storage/volumes/](https://docs.docker.com/storage/volumes/)

---

### Why Use Volumes?

- Containers are **ephemeral**: deleting a container deletes its writable layer.  
- Volumes provide **persistent storage** independent of container lifecycle.  
- Volumes offer **better performance** than bind mounts for most production use cases.  
- Ideal for **databases, logs, configuration files**, or any persistent state.  
- Easier to **backup, restore, and migrate** than container data.  

---

### When to Use Volumes

- **Database Storage:** PostgreSQL, MySQL, MongoDB  
- **Shared Application Data:** files generated by one container and used by another  
- **Logs & Reports:** persistent logs that survive container restarts  
- **Production Deployments:** prevent accidental loss of critical data  
- **Development:** optional, but bind mounts (`-v /host/path:/container/path`) are often preferred  

---

### Key Commands

| Command | Purpose |
|---------|---------|
| `docker volume create <volume_name>` | Create a new volume |
| `docker volume ls` | List all volumes |
| `docker volume inspect <volume_name>` | View metadata, mountpoint, options |
| `docker volume rm <volume_name>` | Remove a volume |
| `docker run -v <volume_name>:<container_path>` | Attach volume to container |
| `docker run --mount source=<volume_name>,target=<container_path>` | Alternative mount syntax |

---

### Example Workflow

```bash
# Create a volume
docker volume create sqldata

# List existing volumes
docker volume ls

# Inspect volume details
docker volume inspect sqldata

# Run container with volume
docker run -d --name my-db -v sqldata:/var/lib/postgresql/data postgres

# Access the container logs to verify
docker logs my-db

# Remove a volume (optional)
docker volume rm sqldata
```
